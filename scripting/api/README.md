# PoEBane script API reference

The authoritative API reference is **`poebane.d.ts`** — TypeScript declarations **generated from the
runtime bindings** (`// @generated by script bindgen`). It is **not committed to this wiki**, on
purpose: a committed snapshot drifts the moment the Rust bindings change, and its `apiHash` would no
longer match the running build.

Instead, the reference is derived from the build, at use time:

## In the app (the in-app Codex assistant)

PoEBane **emits its own build's** `poebane.d.ts` + `poebane.script-api.json` at session start and
mounts them **read-only** in a dedicated directory (separate from this wiki checkout). The assistant
is told where they are and that they are **authoritative for exact signatures** — so the reference
always matches the running binary (same `apiHash` by construction). This wiki carries the
slow-changing prose (concepts, best-practices, examples); the exact API surface comes from the mount.

**If the wiki prose and the generated reference ever disagree on a signature, the generated
reference wins.**

## Offline / external agents

If you are working without the running app, get a current reference from the build itself:

- Read it from your PoEBane checkout at **`src/PoeBane/ui/generated/poebane.d.ts`** (regenerated on
  every build; also `poebane.script-api.json`), or
- Export a guidance pack from the app, which bundles the current `poebane.d.ts` stamped with the
  build's `POEBANE_SCRIPT_API_HASH`.

## Reading it

- **It is the source of truth.** If a global, accessor, method, or field is not declared in
  `poebane.d.ts`, it does not exist in the runtime. Do not invent APIs.
- **`declare global` block = what every script sees.** The top-level `const` / `function`
  declarations (`World`, `Input`, `PlayerValid()`, `PressKey()`, `Log()`, …) are injected as globals.
- **Check the `apiHash`.** The file header's `apiHash` equals the `POEBANE_SCRIPT_API_HASH` global; a
  mismatch against your running build means that copy is stale — regenerate from the build.
