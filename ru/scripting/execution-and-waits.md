# Исполнение скриптов, ожидания и таймеры

Записывайте действия в том порядке, в котором они должны происходить. `Sleep` приостанавливает
эту последовательность, позволяя другим правилам продолжать работу. Для него не нужны `async` и `await`.

```ts
OnTimer(100).Do(() => {
  Info("Starting");
  Sleep(1000);
  Info("One second later");
});
```

Эти примитивы добавляются в POE-81 и пока не выпущены; номер версии будет указан при выпуске.
Руководство применимо к сборкам, в `poebane.d.ts` которых уже есть эти функции. В старых установках,
включая 0.2.140, их нет. Перед использованием проверьте объявления установленной версии.

## Какую операцию выбрать

| Операция | Назначение | Результат |
| --- | --- | --- |
| `OnTimer(period).Do(action)` | Повторять правило, выдерживая `period` миллисекунд после завершения каждого запуска | Настройка правила |
| `Sleep(ms)` или `Wait(ms)` | Продолжить эту последовательность после паузы | `void` |
| `WaitUntil(condition, options?)` | Проверять условие до успеха или истечения времени | `boolean` |
| `setTimeout(callback, ms?, ...args)` | Запланировать отдельный однократный вызов | Числовой идентификатор для отмены |
| `clearTimeout(handle)` | Отменить ещё не начавшийся вызов | `void` |
| `await promise` | Обычное ожидание Promise в асинхронной функции JavaScript | Значение завершившегося Promise |

Длительности задаются в миллисекундах. Аргумент Sleep, настройки WaitUntil и задержка setTimeout
должны быть конечными неотрицательными числами. Дробные значения допустимы. Строки, отрицательные
значения, `NaN` и `Infinity` вызывают ошибку без неявного преобразования. Для Sleep аргумент обязателен;
пропущенная задержка setTimeout равна нулю. Задержка задаёт минимум: продолжение произойдёт на
доступном такте обработки, не раньше срока.

## Одна последовательность сохраняет порядок

Sleep приостанавливает всю текущую цепочку вызовов. Вспомогательные функции, псевдонимы, циклы и
обычные операции над коллекциями сохраняют порядок. Особого ожидающего варианта `forEach` нет.

```ts
function processItem(item: string) {
  Info(`Starting ${item}`);
  Sleep(1000);
  Info(`Finished ${item}`);
}

OnTimer(500).Do(() => {
  ["first", "second", "third"].forEach(processItem);
  Info("All items finished");
});
```

Каждый элемент обрабатывается до конца прежде, чем начнётся следующий. Последнее сообщение появится
после третьего элемента. Так же работают обычный цикл `for` и вложенные функции. Wait — точный
псевдоним Sleep, он не возвращает Promise. `Sleep(0)` уступает управление как минимум до следующего
такта. Sleep не блокирует поток операционной системы и не проверяет время в непрерывном цикле.
Длинный цикл без ожиданий по-прежнему может исчерпать ограничение процессорной работы скрипта.

Локальные переменные сохраняют значения. Другие последовательности могут изменить общие объекты
JavaScript, пока ваша ждёт. После ожидания заново читайте актуальное состояние игры: сохранённые
объекты мира могут устареть после нового такта или смены области. Ранее вычисленный boolean сам не обновится.

## Несколько правил

У каждого правила одновременно занят не более чем один запуск. Он включает условие, действие и
Promise, возвращённый действием. Занятое правило не запускается повторно и не накапливает очередь
пропущенных срабатываний. Другие правила независимы.

```ts
OnTimer(100).Do(() => {
  Info("A started");
  Sleep(1000);
  Info("A finished");
});

OnTimer(100).Do(() => {
  Info("B started");
  Sleep(300);
  Info("B finished");
});
```

Если оба первых запуска начались в нулевой момент, A завершится примерно через 1000 мс и сможет
снова начаться около 1100 мс. B завершится около 300 мс и сможет начаться около 400 мс. Пока A ждёт,
B может выполнить несколько запусков. Реальные моменты определяются доступными тактами; это не
обещание точного срабатывания по настенным часам.

**OnTimer отсчитывает задержку после завершения.** Период начинается после всего предыдущего
запуска, а не в момент его начала. Даже нулевой период требует следующего такта. Догоняющих пачек
нет. Нажатие горячей клавиши или сообщение, пришедшее занятому правилу, не создаёт ещё один запуск.

Интерпретатор исполняет один участок JavaScript за раз. Независимые последовательности чередуются,
когда одна из них ждёт; JavaScript не работает одновременно в разных потоках. Готовые продолжения
и таймеры обслуживаются до новых запусков правил. За проход обрабатывается ограниченная порция
готовой работы; новая работа не запускается рекурсивно в том же проходе. Это тактовый цикл приложения,
а не обещание браузерного порядка обработки событий и микрозадач.

## Ожидание в условии

Sleep разрешён в `.If(...)`. Действие начинается только после того, как условие вернуло true.

```ts
OnTimer(100)
  .If(() => {
    Sleep(500);
    return Input.IsKeyDown(Key.F1);
  })
  .Do(() => Info("F1 is held after the pause"));
```

Клавиша проверяется через 500 мс. Во время условия правило занято. Если результат false, запуск
заканчивается без Do и начинается отсчёт следующего периода. Если перенести чтение клавиши перед
Sleep, намеренно будет проверено более раннее состояние. Значения контекста правила остаются связаны
с тем же правилом после ожиданий и асинхронных продолжений.

## WaitUntil

```ts
OnTimer(100).Do(() => {
  const pressed = WaitUntil(
    () => Input.IsKeyDown(Key.F1),
    { timeoutMs: 5000, pollIntervalMs: 50 },
  );
  Info(pressed ? "F1 pressed" : "Timed out");
});
```

WaitUntil сразу вызывает условие. True немедленно возвращает true. После false следующая проверка
назначается через интервал опроса. По умолчанию это 50 мс; ноль означает не чаще одного раза за такт.
Одновременно выполняется не больше одного вызова условия.

Без `timeoutMs` ожидание продолжается до успеха или отмены. Нулевой предел времени делает одну
немедленную проверку. Успех проверяется раньше срока: true на граничном такте возвращает true.
Завершившаяся проверка false в момент исчерпания времени или позже возвращает false. При необходимости
следующая пауза сокращается до оставшегося времени.

Условие должно возвращать boolean, а не Promise. Исключение распространяется обычным образом.
Stop уничтожает исполнение; ни исключение, ни Stop не превращаются в результат false.

Время проверяется между завершившимися вызовами условия. Если само условие ждёт или долго вычисляет,
истечение времени не прерывает его посреди вызова. Делайте условия короткими и получайте нужные объекты
мира внутри них. Ограничение процессорной работы по-прежнему действует на непрерывные вычисления.

## setTimeout и идентификаторы отмены

```ts
OnTimer(1000).Do(() => {
  setTimeout((message) => {
    Info(String(message));
    Sleep(100);
    Info("Callback finished");
  }, 500, "Callback started");
  Info("Do finished; callback is scheduled separately");
});
```

setTimeout возвращается сразу. Функция начнётся не раньше срока и следующего такта после регистрации.
При одинаковом сроке сохраняется порядок регистрации. Дополнительные аргументы передаются без
преобразования, сохраняя идентичность объектов. Принимаются только функции; выполнение строкового
кода не поддерживается. При вызове передаётся undefined в качестве `this`, далее действуют обычные
правила функций JavaScript.

Функция может вызывать Sleep или возвращать Promise. Само планирование не удерживает вызывающее
правило занятым. Например, правило с периодом 100 мс может накопить много вызовов с задержкой 1000 мс.
Для одной последовательной операции ставьте Sleep непосредственно в правило.

```ts
const handle = setTimeout(() => Info("This will be cancelled"), 1000);
clearTimeout(handle);
```

clearTimeout отменяет функцию до её начала, даже если срок уже наступил и она готова в очереди.
После начала clearTimeout её не прерывает, в том числе во время Sleep. Неизвестные и уже очищенные
числовые идентификаторы ничего не делают. В рамках одного экземпляра среды исполнения идентификаторы
не переиспользуются. Отмена не завершает Promise, ожидающий эту функцию.

Существующие `setInterval`/`clearInterval` используют те же правила планирования и владения отменой.
Интервал назначает следующий вызов в начале текущего, поэтому ожидающие функции могут перекрываться.
Для последовательной повторяющейся автоматизации используйте OnTimer с задержкой после завершения.

## Явные async и await

Обычная семантика Promise в JavaScript сохраняется. Такая обёртка работает без изменений:

```ts
function pause(ms: number) {
  return new Promise<void>(resolve => setTimeout(resolve, ms));
}

OnTimer(100).Do(async () => {
  Info("Started");
  await pause(1000);
  Sleep(500);
  Info("Finished");
});
```

На await действие Do возвращает незавершённый Promise. Правило остаётся занятым до его завершения,
включая последующий Sleep. Только затем отсчитывается следующий период OnTimer. Отклонение Promise
считается ошибкой скрипта, а не успешным завершением. Прямой возврат Promise тоже удерживает занятость:

```ts
OnTimer(100).Do(() => pause(1000));
```

Игнорирование Promise не означает ожидание. Произвольные вызовы автоматически не ожидаются:

```ts
OnTimer(100).Do(() => {
  pause(1000);
  Info("Immediately after scheduling");
});
```

Для повседневных последовательных действий используйте Sleep. Явный асинхронный код требует
обычного понимания JavaScript: `forEach(async item => { await pause(1000); })` не ждёт Promise
своих функций. `forEach(item => { Sleep(1000); })` последователен, потому что Sleep приостанавливает
реальную цепочку вызовов.

### Async не запускает отдельную последовательность

Асинхронная функция начинается синхронно до await или возврата. Sleep в этой начальной части
приостанавливает вызывающий код ещё до возврата Promise:

```ts
async function work(name: string) {
  Info(name);
  Sleep(1000);
}

OnTimer(100).Do(async () => {
  await Promise.all([work("A"), work("B")]);
});
```

Сначала ждёт A, затем начинается и ждёт B. Выражения аргументов вычисляются по порядку.
Если заменить Sleep на `await pause(1000)`, каждый вызов быстро вернёт незавершённый Promise,
поэтому оба таймера смогут быть назначены вместе. Для независимых повторяющихся действий используйте
несколько правил.

## Stop, ошибки и жизненный цикл

События интерфейса скрипта и отрисовка React выполняются последовательно через общий механизм
отрисовки. Если обработчик события или компонент вызывает Sleep, остальные события и отрисовка
интерфейса скрипта ждут завершения этого вызова. Обычные правила, таймеры вне механизма отрисовки
и собственный интерфейс приложения могут продолжать работу. Не рассчитывайте на обновление другого
компонента интерфейса скрипта во время такой паузы. При уничтожении среды ожидающие исполнения
интерфейса отменяются вместе с остальной работой скрипта.

Остановка автоматизации уничтожает её активные исполнения, ожидающие цепочки вызовов, отложенные
функции и продолжения Promise. Повторное включение создаёт новые исполнения: старые не могут
проснуться и отправить ввод. Владелец функции определяется местом её регистрации, а не правилом,
которое позже разрешило её Promise. У независимых действующих подписчиков одного Promise свои сроки жизни.
Пустой `.then()` тоже регистрирует продолжение с этим владельцем. После отмены ни передача результата
дальше, ни пользовательский код разрешения результата Promise не могут оживить уничтоженную последовательность.

Stop **не исполняет** JavaScript `finally` на уничтожаемых цепочках вызовов. Приложение само
освобождает отслеживаемый удерживаемый ввод. При нормальном завершении и обычном исключении
JavaScript try/finally работает. Не полагайтесь на finally для аварийной очистки при уничтожении исполнения.

Если другой Promise зависит от результата уничтоженного исполнения, он может остаться незавершённым.
Stop не подставляет выдуманное успешное значение и не возобновляет старые catch/finally исключением отмены.

Инициализация верхнего уровня и зарегистрированные функции жизненного цикла принадлежат среде скрипта;
они отличаются от исполнений правил автоматизации. OnAutomationInactive вызывается при переходе из
активного состояния в неактивное. Его собственное ожидающее продолжение может жить при выключенной
автоматизации, с прежними ограничениями на очистку и ввод. OnUnload не продлевает жизнь среды: у каждой
функции очистки выполняется только синхронная часть до первого ожидания, затем среда уничтожается.

## Удержание клавиши

```ts
OnTimer(100).Do(() => {
  Input.KeyDown(Key.Space);
  try {
    Sleep(1000);
  } finally {
    Input.KeyUp(Key.Space);
  }
  Sleep(100);
});
```

При обычном исполнении Space удерживается не меньше секунды, отпускается, затем следует ещё 100 мс
ожидания. Stop во время удержания отпускает клавишу через приложение, хотя JavaScript finally не исполняется.

Для авторов на базе AI: используйте Sleep/Wait/WaitUntil непосредственно в последовательных правилах;
сохраняйте обычные вспомогательные функции и циклы. Не добавляйте async ко всем функциям, не заменяйте
операции коллекций и не изобретайте автоматическое ожидание Promise. Для случайных чисел достаточно
обычного `Math.random()`.

Ключевые слова: sleep, wait, delay, pause, foreach, timeout, condition, polling, timer, cancellation,
последовательность, ожидание.
