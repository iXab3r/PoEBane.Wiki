# Скрипты PoEBane — лучшие практики

## Делайте

- **Сначала смотрите типизированный API.** `poebane.d.ts` генерируется из привязок рантайма и является
  источником истины. Ищите точную сигнатуру там, а не угадывайте.
- **Защищайте чтение живого состояния через `PlayerValid()`.** `World.Player` — это `Entity | null`, и
  большая часть состояния имеет смысл только в игре. Сначала проверяйте `PlayerValid()` (и `World.Player`
  на `null`).
- **Держите тело тика дешёвым.** Скрипт выполняется в игровом цикле. Делайте на тик минимум: прочитайте
  нужные поля, ветвитесь, действуйте. Избегайте аллокаций и тяжёлых циклов на каждый тик.
- **Предпочитайте аксессоры.** Читайте сущности/флаконы/инвентарь/UI через аксессоры `World.*` — они
  корректно читают живую нативную память. Не вычисляйте адреса и смещения сами.
- **Предпочитайте высокоуровневые переключатели.** Для стэша/фарма/следования/подбора используйте
  `SetAutoStash` / `SetAutoFarm` / `SetAutoFollow` / `SetAutoPickup`, а не реализуйте это заново из
  примитивов.
- **Логируйте на правильном уровне.** `Trace`/`Debug` для деталей, `Info` для обычных событий,
  `Warn`/`Error` для проблем. `console.log(...)` тоже работает.

## Не делайте

- **Не сериализуйте весь мир в JSON в горячем цикле.** Аксессоры `World.*` — это живые привязки к
  нативной памяти. Прочитать поле дёшево; сериализовать большие графы аксессоров (или
  `JSON.stringify`-ить их) каждый тик — это большая аллокация и нагрузка на GC. Читайте только нужные
  поля.
- **Не блокируйте игровой цикл.** Долгие ожидания, busy-wait или синхронное сглаживание ввода тормозят
  автоматизацию. Держите управление мгновенным: делайте дискретные действия и возвращайтесь.
- **Не хардкодьте смещения, адреса или пути метаданных из памяти.** Используйте аксессоры и поля
  `Entity.Path` / `Entity.Metadata`. Адреса меняются от запуска к запуску.
- **Не выдумывайте API.** Если глобала, аксессора, метода или поля нет в `poebane.d.ts` — его не
  существует. `apiHash` в этом файле должен совпадать с `POEBANE_SCRIPT_API_HASH` рабочей сборки;
  несовпадение значит, что документация устарела — перепроверьте.
- **Не считайте слой реактивных правил завершённым.** `Group` / `OnTimer` / `OnHotkey` возвращают
  контекстные объекты; прежде чем полагаться на них, проверьте в `.d.ts`, что нужная сторона действий
  подключена. Императивная часть (чтение + `PressKey`/`SetAuto*`/`DisplayText`/логирование) стабильна.
